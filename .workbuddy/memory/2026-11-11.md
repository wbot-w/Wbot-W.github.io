## 修复：双击 index.html（file://）显示不完整

- 现象：`file://` 下浏览器拦截 `fetch('contents/config.yml')` 与各 `.md`，config 加载失败 → 标题 / 导航 / 6 个分区全空，只剩静态骨架（headless Edge dump-dom 复现：sections=0、nav=0、title 为空）。
- 方案（双模，同一份 index.html）：新增 `tools/build-offline.js` 读取 `contents/` 生成 `static/js/offline.js`（7 份文本快照）；在 `scripts.js` 之前加载，仅在 `location.protocol === 'file:'` 时劫持 `window.fetch`，对 `contents/*` 返回内联 `Response`，其他请求仍走原生 fetch。线上 http/https 完全不介入，config + Markdown 驱动流程不变。
- 配套：`scripts.js` 的 `allowedUrlProtocols` 在 file: 下追加 `'file:'`（用 `window.location` 存在性保护，保证 vm 测试不报错），否则 `sanitizeMarkdownHtml` 会把相对 `src` / `href="#"` 当成不安全协议删掉，导致项目 SVG、头像、筛选链接失效。
- 验证：file:// 下 6 sections / 6 nav / 3 cards / 3 SVG 图片 `naturalWidth>0` / 头像 / hud.svg 背景 / 标题 / 高亮全部正常；筛选 1/2/3、主题切换、打印按钮、复制邮箱、详情展开均正常；整页截图与 http:// 版一致。http:// 下仍 6 sections / site-ready。两个模板测试通过。
- 维护约定：**改过 contents/ 里的 config 或 md 后，必须运行 `node tools/build-offline.js` 重新生成快照**，否则双击看到旧内容。已用 vm 校验 7 份快照与 contents/ 逐字一致。
